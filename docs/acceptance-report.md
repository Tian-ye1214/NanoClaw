## 主要改动与修复

- CLI 与机器人复用 FIFO 队列；普通/目标回合共用启动与异常处理；子 Agent 的线程、循环和客户端由工厂释放。
- 正式记忆统一由 LanceDB `memory_records_v3` 保存；原始轨迹、引用和生产 jobs 各有明确职责。25/5 窗口调用 LLM 聚合后索引，保留 embedding、rerank、项目过滤和文本降级。
- 同一 job 的主动执行和后台恢复互斥，成功结果直接复用。纠正按原始事件及请求登记时间排序；旧请求提交较晚也不能覆盖新事实。
- 索引与召回失败可见，收尾意图持久化，重启会补处理暂停任务。旧 requests / production / receipts 与核心文档缓存先备份再迁移；成功生产不因升级重新请求模型。
- 文件引用使用统一快照与解析器；Office 图片关联正文位置，LibreOffice 使用短临时路径处理 Windows 深目录。浏览器改用异步会话，Skills 工具直接由管理对象提供。
- 文件写入与审查快照共用一次锁定操作；撤销反馈进入当前回合，防止模型重新写回。界面之外的修改得到保留。
- 用量从完整轨迹统计，去除重复显示版本，推理 token 不再重复累加。CLI/TUI 共用命令、补全和统计逻辑。

此前失败没有计作通过：第 8 组发现 compressor 没有独立上下文段时读取预算失败，已修复并在之后三组复测；此前还修复了工具选择协议、取消后的空助手消息、Office 长路径、撤销反馈丢失等真实问题。

生产源码由 16,181 行变为 14,470 行；新增的测试与验收脚本单独保留。行数作为统计，最终以清晰职责与行为验证为准。
